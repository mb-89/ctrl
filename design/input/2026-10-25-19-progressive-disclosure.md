# Progressive disclosure; the System library's descriptions (2026-10-25)

> And then I feel like if I look at the system library and the descriptions of the models, they are too long. Look at how long the DC motor thing is. Yeah, you can send a worker to clean that up. In general, think about progressive disclosure, right? There should be a bottom line that you show in the library, and then the model can have a detailed description in the plan somewhere, so we can click and see a detailed description of it. But yeah, what we currently have in the system library is too much. In general, think about progressive disclosure. On a user interface, in general, what you need to show is what's actionable and needed for a decision. The details you can hide behind the details button or something like this.

> Like the fact that the oven is has an overshoot of 67 and 52 degrees, that doesn't matter. Like, to decide which model to show, I don't need to know the numeric values of stuff like this. This is similar in the other examples.

> So what the user needs to see in the library is, what is the model? Which features does it present? What can you try out with this model? What can you learn from it?
