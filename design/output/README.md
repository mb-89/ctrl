# Design output

Reader: an agent or person about to change Loop Tuner. Read this folder before you start; it is what was decided, so nobody has to explain it twice.

The person's raw words are in [../input](../input/README.md). This folder is what we made of them. When the person gives new direction: save their words verbatim in `input/`, then update the documents here, and add a line to the decision log.

## Status (2026-10-24)

- Repository: [github.com/mb-89/ctrl](https://github.com/mb-89/ctrl).
- **v1** (commit `b13ff03`): everything on one screen: scope, goal, candidates, a rack of knobs, auto-tune. It works, but the person found it overloaded; it is superseded by v2.
- **v2, in progress**: the oscilloscope layout with the Input tab (signal generator) and the Plant tab (block diagram) built. The screen is the record; the display can be zoomed and panned directly. Until a controller exists, the diagram is the whole system: Sources play signals, Sinks are what the scope shows. Every signal has a unit. Plants carry 2D views (JSON only); three systems load from the System library and open running on their view. The Controller tab is built: Controller blocks hold variants (PID, state feedback, gain scheduling, Lyapunov swing-up, relay) and the library has four controlled systems up to a triple pendulum. The Auto-tune tab is built: Nelder–Mead on a simulated cost, relay feedback, step response with SIMC (since the person's report, also for integrating plants such as the DC motor, through ripple, and per point of a gain schedule), and a badly tuned oven to try them on; agents run the same with `node cli.mjs autotune` ([autotune.md](autotune.md)). The Analysis tab is built and its review's findings fixed (gain interval at z = ±1, a loop-derived frequency grid, the DC-gain final value, poles on the circle, marginal loops, exact fractional dead time); it waits for the design layer's plant model (`app.loopModel`, branch `feat/designs`) and says so until that is merged ([analysis.md](analysis.md), [roadmap.md](roadmap.md)). The scope has an XY mode with Δ for the error over the reference ([instrument.md](instrument.md)).
- **v2.7, Live (HIL) and saving traces** ([hil.md](hil.md)): a system's plant can run outside the page (`hil-plant.zip`: `hil_plant.py` with runme scripts that install what it needs), at 100 Hz over a WebSocket, with watchdogs and a stop on both sides; the scope's Run and Stop go through the plant, and the controller is tuned against it while it runs. Save stores the screen with every signal (CSV, JSON) or as a picture; the live record keeps the last minutes of live data; saved traces show as references ([instrument.md](instrument.md#save-the-live-record-and-references)). **Speed** in the header sets how fast simulated time runs (1× real time, any factor, ∞ as fast as the page simulates the screen, which no speed exceeds) and shows the speed achieved; Auto-tune runs at it (its Fast switch is gone), each run lasting its own length, and a live plant holds it at 1× ([instrument.md](instrument.md#speed); revised after review, decisions.md).
- **v2.7, sliding mode** ([decisions.md](decisions.md), research: [../research/sliding-mode.md](../research/sliding-mode.md)): the `slidingMode` (relay, boundary layer) and `superTwisting` controller types and *DC motor, sliding mode*, which opens on the phase portrait (XY without Δ); the motor's Motor is built from Transfer function blocks whose coefficients are R, L, J and b, with its current as a Sink; a Measure line per scope channel (mean, rms, ac, p-p, TV/s, reversals/s, an under-resolved warning); controllers sample exactly at k·Ts; a library entry may carry its record step.
- **Identify, designed** ([identification.md](identification.md)): a tab between Controller and Auto-tune, so Auto-tune and Analysis work for HIL plants the page does not know. Experiment first, for a tester with no control theory (the person's decision, input 10); not built yet.
- The simulation core (`src/core/`) and the agent CLI (`cli.mjs`, see `AGENTS.md`) carry over from v1.
