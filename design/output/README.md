# Design output

Reader: an agent or person about to change Loop Tuner. Read this folder before you start; it is what was decided, so nobody has to explain it twice.

The person's raw words are in [../input](../input/README.md). This folder is what we made of them. When the person gives new direction: save their words verbatim in `input/`, then update the documents here, and add a line to the decision log.

## Status (2026-10-25)

- Repository: [github.com/mb-89/ctrl](https://github.com/mb-89/ctrl).
- **v1** (commit `b13ff03`): everything on one screen: scope, goal, candidates, a rack of knobs, auto-tune. It works, but the person found it overloaded; it is superseded by v2.
- **v2, in progress**: the oscilloscope layout with the Input tab (signal generator) and the Plant tab (block diagram) built. The screen is the record; the display can be zoomed and panned directly. Until a controller exists, the diagram is the whole system: Sources play signals, Sinks are what the scope shows. Every signal has a unit. Plants carry 2D views (JSON only); thirteen systems load from the System library and open running on their view. The Controller tab is built: Controller and Observer blocks hold variants, set by hand (PID with feedforward and anti-windup, state feedback, gain-scheduled PI, Lyapunov swing-up, relay, sliding mode, super-twisting, a Kalman filter on a model you give, Luenberger observer, finite differences) or computed in the page from the plant as it is wired (LQR, PI from the plant, a PID's feedforward from the plant's inverse, swing-up with an LQR catch, a planned swing-up with TV-LQR, Kalman filter, Luenberger observer with placed poles); nothing plant-specific is stored ([designs.md](designs.md)); a small diagram shows what the running variant does. The library has eleven controlled systems, up to a triple pendulum that swings itself up from hanging; one estimates a motor's speed from its encoder with an Observer (v2.8). The Auto-tune tab is built: Nelder–Mead on a simulated cost, relay feedback, step response with SIMC (also for integrating plants such as the DC motor, through ripple, and per point of a gain schedule), and a badly tuned oven to try them on; agents run the same with `node cli.mjs autotune` ([autotune.md](autotune.md)); a variant from the plant is tuned as its Copy as numbers twin. The Analysis tab is built and draws the loop from the design layer's models (`app.loopModel`: the plant the block sees, linearised at rest, at the start or at the scope's time, and the running variant's law), with a reason where a law has no linear model ([analysis.md](analysis.md)). The scope has an XY mode with Δ for the error over the reference ([instrument.md](instrument.md)). The design layer (branch `feat/designs`, reviewed twice, decisions v2.7.1) is merged with main (decisions v2.7.2) and was reviewed in the browser after the merge (v2.7.3: the Analysis tab grades no loop where the linear model does not hold; Auto-tune does not run an experiment's result that is unstable where the run starts; the header no longer jumps while a plan is made). v2.7.4 merged main twice more (the design system, the robot core, the HIL plant as a black box) and fixed what three reviews found: a Dead time that delayed a held u half a step short, the tank dropping a draw-off larger than the pump, the Analysis tab drawing a kink's meaningless slope, Ms read off the grid, a sliding mode's prefilter missing from its model, a live loop rebuilt by a design that did not run, the sine's hand feedforward that was the plant's inverse (now computed, `pidFF`), files with a typed-in Kalman model refused (now `kalmanModel`), and the source archive in `dist/`; open: super-twisting's k2 and the plan in a Worker (roadmap).
- **v2.7, one design system** ([design-system.md](design-system.md), the person, input 10): every style in one sheet, from tokens; one button (the instrument's key, default or danger; no primary); one selected look everywhere: the key, tab or row lights up (violet for a selection, a channel's colour, green/red/amber for run states); the typefaces carried in the page, which loads nothing.
- **v2.7, Live (HIL) and saving traces** ([hil.md](hil.md)): a system's plant can run outside the page (`hil-plant.zip`: `hil_plant.py`, with a window holding a red STOP, and runme scripts that install what it needs), at 100 Hz (200 Hz measured sound) over a WebSocket, with watchdogs and a stop on both sides; the scope's Run and Stop go through the plant and nothing runs by itself; the references ramp in at 10 % of full scale per second and every channel spans its full scale; two modes, control (the page sends u, with r and e for the plant's log) and reference (the plant controls itself; the page's controllers are not in the loop). The Live controls are in the Plant tab's right-hand panel, E-STOP in the header. Single while running finishes the run. The page documents itself for agents with only a browser (`loopTuner.help()`, Help › For agents; named in every page's head), and every key answers through the API. Who latched an E-stop resets it (a STOP at the plant only there); keys pressed faster than the plant answers end as the last one says (fixed after two reviews, [hil.md](hil.md#after-review-2026-10-25)). Save stores the screen with every signal (CSV, JSON) or as a screenshot; the live record keeps the last minutes of live data; saved traces show as references ([instrument.md](instrument.md#save-the-live-record-and-references)). **Speed** in the header sets how fast simulated time runs (1× real time, any factor, ∞ as fast as the page simulates the screen, which no speed exceeds) and shows the speed achieved; Auto-tune runs at it (its Fast switch is gone), each run lasting its own length, and a live plant holds it at 1× ([instrument.md](instrument.md#speed); revised after review, decisions.md).
- **v2.7, sliding mode** ([decisions.md](decisions.md), research: [../research/sliding-mode.md](../research/sliding-mode.md)): the `slidingMode` (relay, boundary layer) and `superTwisting` controller types and *DC motor, sliding mode*, which opens on the phase portrait (XY without Δ); the motor's Motor is built from Transfer function blocks whose coefficients are R, L, J and b, with its current as a Sink; a Measure line per scope channel (mean, rms, ac, p-p, TV/s, reversals/s, an under-resolved warning); controllers sample exactly at k·Ts; a library entry may carry its record step.
- **v2.8, the HIL simulator runs any library model** ([hil-simulator.md](hil-simulator.md)): the downloadable plant simulates any System library model (or one at random) with the page's own core, cut into the zip from the page's script and run in V8 inside the Python plant (mini-racer, installed by uv); it varies the physics and switches the model's effects from one seed and tells the page only the interface; sample for sample the page's simulation; 100 and 200 Hz measured.
- **v2.8, model foundations** (branch `feat/model-foundations`; [decisions.md](decisions.md)): the steps four plans share, built once: pass nodes elided (runs 10–35 % faster), the eigenvalue step bound in `el.bound` (a fast loop of Integrators gets its step; no library step changes), the run's warnings on the status line and in `loopTuner.info()` and `node cli.mjs run`, formulas and subsystem masks with the mask panel, Equations (the Function block with named inputs and outputs) and the Integrator with start value and limits ([transparent-models.md](transparent-models.md) steps 1–3, [detail-levels.md](detail-levels.md) steps 1–2).
- **v2.9, an MCP server and the agentic mode** ([mcp.md](mcp.md)): `node mcp.mjs` serves the core to an agent over MCP (2026-07-28 and the revisions with `initialize`), with no dependencies, and serves the page: a page it served connects back, and the agent works on the page the person sees (page_ tools, data summaries first). Downloadable from the page (Export ▾ › MCP server), with runme scripts that install Node.js. The CLI and the server share `src/core/ops.js`; the CLI gained `run` and `analyze`. Checked with a real client (Claude Code) on the DC motor, and in Chromium against the real HIL plant. The header's file keys are one Export menu; reference mode is a switch in Live settings; *HIL with an agent* joins the library.
- **Identify, designed** ([identification.md](identification.md)): a tab between Controller and Auto-tune, so Auto-tune and Analysis work for HIL plants the page does not know. Experiment first, for a tester with no control theory (the person's decision, input 10). Step 1 built: each output's hard range in `describe` (the plant E-stops beyond it) and the inputs the plant applied in each `y`, both optional; the rest not built yet.
- The simulation core (`src/core/`) and the agent CLI (`cli.mjs`, see `AGENTS.md`) carry over from v1.
